## 1. 何を作るか

**AIおかん** — 自分以上に自分を理解しているAIが、目標達成まで外圧をかけ続けるアプリ。

Discord `#アイデア出し` で固まったコンセプト（12:11 okita）:

1. 自分以上に自分を知ってくれている（過去の自分のデータを全て知っている）
2. 目標を入れると、自分の目標に向かってエンゲージしてくれて、目標達成率を高めてくれる
3. 途中のフィードバックをくれる
4. 達成できなかったら厳しく叱ってくれる（罰金）

## 2. 解きたい課題

- **課題**: 目標を管理できない（11:43 児玉）
- **解決したいこと**: AIを使って進捗管理をして、目標への到達度合いを図る
- **10年後要素**: 自動入力（人が意識しなくても入力できる）／動画・画像・ウェアラブル・音声のマルチモーダル入力

既存の目標管理アプリが機能しないのは「記録を人間が能動的につけ続ける必要がある」ため。AIおかんは **エビデンス（写真）を出させる外圧** と **自分で決めた罰金** で、記録と継続の両方を成立させる。

## 3. 体験（＝デモの筋書き、4ステップ）

| # | 画面 | 何が起きるか | 審査基準への効き |
|---|---|---|---|
| 1 | あんたのこと、教えて | Gmail / X / LINE のエクスポート想定データを投入 | 実現性（実在するエクスポート形式） |
| 2 | おかんの見立て | AIが過去ログから人物像を生成し、挫折パターンを言い当てる | 価値・AIの活かし方 |
| 3 | 約束 | 目標・期限・エビデンス形式・**罰金額を自分で決める** | 新規性（褒めるAIではなく外圧をかけるAI） |
| 4 | 監視と制裁 | 写真をアップ→マルチモーダルAIが真偽判定→褒める or 激詰め＋罰金発動 | 新規性・AIの活かし方 |

**設計上の要**: 叱られるのではなく「自分で結んだ約束」の形にする。罰金額を本人に決めさせることで、制限型の押し付けではなく自己拘束（コミットメント・デバイス）として成立させる。

## 4. アーキテクチャ

- Next.js (App Router, TypeScript, Tailwind) / Vercel
- 状態は **localStorage のみ。DBなし**（ハッカソンのスコープとして意図的に持たない）
- API は2本
  - `POST /api/okan` — 人物プロファイル生成・叱責/称賛の文面生成
  - `POST /api/verify` — 提出画像がエビデンスとして妥当かの判定（マルチモーダル）
- `lib/llm.ts` が provider を吸収する。環境変数で自動選択:
  - `GEMINI_API_KEY` があれば Gemini
  - なければ `OPENAI_API_KEY` で OpenAI
  - どちらも無ければ **デモモード**
- SDKは使わず `fetch` 直叩き（依存を増やさず、起動と実行を軽くする）

### デモモード（必須要件）

APIキーが無い場合・API呼び出しが失敗した場合・タイムアウトした場合は、事前に用意した応答にフォールバックして **同じ画面遷移が最後まで通る**。審査本番でAPIが落ちてデモが死ぬ事故を防ぐための保険であり、機能の劣化版ではなく **フェイルセーフ**として実装する。

## 5. 受け入れ条件（検証手段）

1. `npm run build` がエラーなく完了する
2. `npm run dev` で 4ステップすべてを実際に操作して通過できる（スクリーンショットを提示）
3. `vercel --prod` のURLで同じ4ステップが通る
4. **APIキーを外した状態**でもデモモードで4ステップが通る

## 6. やらないこと（YAGNI）

- ユーザー認証・アカウント作成
- データベース、サーバー側の永続化
- 実際のGmail / Instagram / X との OAuth 連携（**形式だけ合わせたサンプルデータで代替する**。実現性の説明は口頭とREADMEで行う）
- 実決済（罰金は画面上のモック）
- ウェアラブル連携（展開性として語るのみ）

## 7. 展開性（審査での説明用）

- コミュニティ版: 自分以外のコミュニティに属する人も使う（11:30 児玉）。約束の相互監視
- 自動入力: ウェアラブル・写真・音声を自動で取り込み、人が意識せず記録される（10年後要素）
- おかん以外の人格: 性格はAIとチューニング可能（12:09 児玉）
